## Moneris integration (verified working pattern)

For any Moneris HT iframe + MPG Purchase API integration on either repo:

- HT profile Source URL must be origin only, e.g. `https://events.sulaindianrestaurant.com`. No trailing slash, no path prefix. Trailing slash and path prefix variants both reject with code 942.
- Tokenize trigger is the literal string `'tokenize'` posted to the iframe's exact origin (NOT `'*'`, NOT an object wrapper).
- `pmmsg=true` query param locks the iframe to only accept the literal `'tokenize'` message.
- `css_body` and `css_textbox` query params are required, not optional.
- HT data_keys go through the `<res_purchase_cc>` MPG transaction (NOT `<purchase>`, that's for raw card data).
- Diag endpoints for credential issues: `/api/moneris-debug` (env shapes only, no values), `/api/diag-moneris` (live MPG auth probe). Probe response code 983 "Can not find previous" is the GOOD signal (auth passed, fake data_key correctly rejected).
- Verified working credentials live on sula-events: store `gwca086878` (SULA DAVIE STREET), HT profile `ht7COODHAOT7FM8`. If sula-catering ever needs payments, follow the same setup pattern.
